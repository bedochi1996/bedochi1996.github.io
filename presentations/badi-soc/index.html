01 — The console

One interface an analyst works a shift in

Twelve screens in four groups — Operations, Analysis, Governance, Training — all reading one database. An analyst does not change product to move from working a queue, to running a scored drill, to reading the compliance register.

02 — Triage

The queue, and the clock nobody was watching

An analyst triages under time pressure and compares rows. Everything on this screen exists to keep a comparison cheap: the queue does not reorder itself, the selection survives a filter change, and the response target is a marker on the row rather than a number in a settings page nobody reads.

03 — Auto-triage

A verdict that shows its arithmetic

Five weighted terms, published thresholds, and three floors for the cases where a weighted average is the wrong instrument. The same alert always returns the same verdict, which is what lets a drill be repeated and marked — and lets an analyst argue with one line rather than with a black box.

04 — Threat intelligence

Every figure says where it came from

Three providers queried concurrently, each failing independently. The half that matters is not the lookup: it is that a source which did not answer is never painted in the colour of a clean verdict.

05 — Investigation

The case file, built from what was actually done

An incident is worked across shifts. The escalation trail carries the reason written at the time, and the timeline is the only input the report generator has — so an undocumented investigation produces a thin report rather than a fabricated one.

06 — Coordination

The war room, and the handover

Two things a centre does badly when it does them in chat.

07 — Governance

NCA ECC, advanced by the work itself

Thirty Essential Cybersecurity Controls across five domains, in the same database as the alerts. The score is not stored — it is recomputed on every read from the control statuses, so there is no cached figure to go stale and no way to set it directly. Controls advance when an incident is resolved, an alert escalated or a playbook run completed, and the same piece of evidence can only count once.

08 — Reporting

Twelve screens, twelve documents, two languages

Every screen exports a printable document built from the data the page already holds. Nothing is re-fetched, so a report cannot disagree with the screen the analyst was reading when they pressed the button — filtered rows included, filtered-out rows excluded, and a scope line saying which.

09 — Coverage

ATT&CK as a measurement, not a slide

A fixed catalogue of 12 tactics and 31 techniques with a computed overlay. Coverage never comes from the catalogue — it is a grouping over the technique field of the alerts that actually fired, so the matrix cannot claim a cell the data does not show.

10 — Attribution

A threat map that refuses to invent geography

Most threat maps are decoration with invented data. This one draws only alerts whose source address is actually known, places the estate at one fixed location because an alert carries no city of its own, and has no "blocked" figure at all because nothing in the schema records a block.

11 — Procedure

A playbook run is evidence, not a document

Six response procedures, 37 steps between them, each step carrying what to do and the role that owns it. Every tick is persisted with the analyst's name and the time, because evidence that vanishes on refresh is not evidence.

12 — Training

Drills on the console, not on a separate range

Three guided reconstructions of known intrusions — SolarWinds, Log4Shell, brute force and privilege escalation — seven phases in total, each with three options and a countdown. The answer key never ships to the browser, and the server re-grades every phase at completion.

13 — Measurement

A ledger, not a vanity number

Thirteen point types with fixed values, nine positive and four negative. Every award carries a reference — the alert, the incident, the playbook, the scenario — and a repeat for the same analyst and reference pays zero. A scoreboard anyone can farm with a request loop measures nothing.

14 — BADI AI

An assistant that declines rather than invents

Every question carries a freshly read snapshot of this deployment — total alerts, open counts by severity, the six highest-risk open alerts, the four most recent open incidents — followed by an instruction that this list is the whole of what it can see, that anything else must be answered by naming the screen which holds it, and that it must never invent an alert, a hostname or a number.

  • Model output is untrusted input. The reply is parsed into headings, steps, tables and code and rendered as interface nodes, never HTML, so a model that emits a script tag renders it as text.
  • It deliberately under-interprets. Underscores mark nothing, because the product is full of identifiers like svc_backup2; italic must open and close on word boundaries, so *.exe and *.dll keeps its asterisks; only http and https become links.
  • A "system" turn is impossible. The conversation window is typed, so an instruction smuggled through the history is rejected by the type rather than by a check — and there is a test that asserts exactly that.
  • Failures read as operational facts. One short sentence in the analyst's own language, not a stack of provider JSON.

15 — Both languages

Arabic that survives the layout, and the print

English is the default and Arabic is one click away, flipping both the strings and the direction. 736 translation keys in each language, counted at the same number, with the Arabic dictionary typed against the English one so a missing key is a compile error rather than a blank on screen.

16 — The visual system

Declared once, enforced by a machine

Every colour, type size, radius, shadow and density value is declared once as a token and consumed everywhere, across three surfaces of the same set: light, dark and paper. A hex literal outside the two permitted files fails the build, as do emoji, gradients, backdrop blur, coloured glow, decorative animation and an oversized radius. The check runs on every branch.

  • Severity is never colour alone — a dot, the word, and a tint. A queue where criticality is a hue fails for roughly one man in twelve, and for every printed copy.
  • The brand accent is never a severity, and a severity pigment is never used for a primary button.
  • Every number on screen comes from the API, and a figure derived in the browser says so next to itself.
  • A row that is not clickable does not look clickable — a table with no action gets no pointer cursor, no hover tint and no tab stop.
  • Two abandoned directions are recorded with the reason each lost, and encoded as lint rules so neither can return by accident.

17 — Running it

What an operator can see and change

The settings screen is the one place that states what is actually wired up, and the sign-in wall is built on every data endpoint even while it is switched off for this demonstration.

18 — Verification

The counts come from running the suites

Four jobs run on every branch and every pull request. Three of them block a merge: the backend suite against a real database with a coverage floor, the design lint, and the frontend's type check, lint, unit tests and a real production build.

  • The trigger was itself a defect. It named three branches, none of which carried any work, so the gate had never run on a single commit. The note left in the workflow reads: a gate nobody passes through is not a gate.
  • The named suites are the interesting ones — migrations, the outbound-request guard, access control and object references, war-room authentication, token revocation, open-access mode, the response envelope and point farming, scoring integrity, and triage agreement with the queue above it.
  • The test fixtures cannot touch the wrong database. They drop every table, so the target is assigned rather than defaulted and refused unless its name ends in a test suffix — because inheriting the variable had emptied the development database more than once.
  • One end-to-end test asserts that the sign-in page does not print credentials.
  • Five decision records state their own unfixed edges rather than their benefits, including in bold that restarting the backend brings revoked tokens back to life until they expire.

19 — Who it is for

Four roles, first day

L1 analyst

Works a queue and is told why

A queue with severity, an auto-triage verdict with stated reasoning, and response-target markers. Escalates with a recorded trail, opens the log lines behind any alert, runs scored scenarios, sees their own points. Cannot send an indicator to a public provider.

L2 analyst

Builds the case

Opens an incident, builds a timeline, enriches indicators with per-source provenance, starts a playbook run tied to that incident, and is shown the closed incidents that resemble the one in front of them.

L3 / detection engineer

Reads coverage as a measurement

The full ATT&CK matrix with coverage derived from the techniques real alerts map to, the named gaps, and access to the compliance register.

SOC manager

Reads a ledger, not a summary

Analyst performance as individual point events with their reasons, including the negative ones; the compliance register and its export; a generated shift handoff; a printable report from any screen.
